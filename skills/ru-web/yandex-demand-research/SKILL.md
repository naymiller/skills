# Исследование спроса перед сайтом (Яндекс и Google)

Что нужно: браузер с входом в Яндекс (для Вордстата и Вебмастера; без входа этапы помечаются «без частотностей»), WebSearch/WebFetch для открытых страниц. API-ключи и Python не нужны. Агенты — любые, которые умеют работать с браузером или поиском (например, отдельные агенты на дешёвой модели).

Что здесь есть: сквозной путь до сборки сайта на русскоязычном рынке. Вордстат, подсказки Яндекса, выдача топ-10, ответы нейросетей (Алиса, ChatGPT, Perplexity), Яндекс Карты и 2ГИС, конкуренты. Из этого получается карта страниц с title и description, план статей, факты для llms.txt и robots.txt, FAQ. Всё снимается через браузер, без API.

Сайт строится от того, как ищут люди, а не от того, как мы называем услугу: сначала спрос, потом структура, тексты, llms.txt, robots.txt, статьи. Исключение — пользователь прямо сказал «без исследования».

## Правила
- Цифры не выдумываются. Частотность, показы и позиции берутся только из снятых источников. Нет данных — пишем «в данных нет» или «недоступен — причина».
- Тексты конкурентов не копируются. Берутся структура и факты, формулировки свои.
- Ничего не отправляется в поисковики и живой сайт не меняется. Этот скилл только исследует; отправка URL и правки — отдельное решение пользователя.
- Тексты страниц пишите по своим правилам; скилл даёт структуру и факты.
- Пользовательские данные (кабинеты Вебмастера, Вордстата, выгрузки) не публикуются и не попадают в результат без нужды.

## 0. Вход и делегирование
- Семя: ниша, регион, услуги и синонимы (например, «трафаретная печать» = «шелкография»), целевые клиенты, цены «от», минимальный тираж. Чего нет — спросить пользователя.
- Одной строкой сказать, что отдаётся агентам (параллельно, до 5 одновременно, на крупных задачах до 10): выдача и подсказки, конкуренты, нейросети, карты. Себе — Вордстат в браузере с входом, кластеризация, выводы.
- Каждому агенту дать бриф: запросы, регион, куда сохранять (CSV или MD в рабочей папке проекта `research/`), правило «не выдумывать цифры».
- Срок этапа — часы, не дни. Вордстат недоступен — работать по подсказкам, выдаче и Вебмастеру, пометить «без частотностей».
- Готово, когда: семя записано (ниша, регион, услуги и синонимы, цены «от», минимальный тираж), распределение «себе / агентам» названо пользователю одной строкой.

## 1. Источники (references/sources.md — как снимать каждый)
1. **Вордстат** — частотность по региону сайта и по России, точная `"!фраза"` и в кавычках, сезонность, устройства. Главный источник для РФ.
2. **Подсказки** Яндекса и Google по корням («производство мерча», «мерч на заказ», «печать на футболках») и «люди также ищут» / People Also Ask — реальные формулировки и вопросы для FAQ.
3. **Выдача топ-10** Яндекса и Google по 10–20 запросам (по 2–3 на кластер) из региона сайта: кто стоит, тип страницы, что в title и сниппете, есть ли карты и нейроответ.
4. **Свои сайты**, если есть: Вебмастер (поисковые запросы за 12 месяцев) и Search Console — запросы, по которым сайт уже показывается.
5. **Нейросети**: одни и те же 5–8 вопросов в Поиске с Алисой, ChatGPT, Perplexity — кого цитируют, какие факты выводят (цена, тираж, адрес, срок), в каком формате.
6. **Конкуренты** (3–5 из топа, не агрегаторы): структура URL, шаблон title, страницы по тиражам, методам и изделиям, где видна цена, FAQ, что на первом экране.
7. **Карты**: рубрики Яндекс Карт и 2ГИС, в которых стоят конкуренты, названия услуг в их карточках, частые слова в отзывах.
- Готово, когда: по каждому из 7 источников есть файл со снятыми данными либо запись «недоступен — причина»; ни одна цифра не взята из памяти.

## 2. Кластеризация (references/method.md)
Таблица `research/queries.csv`: запрос | точная | широкая | регион | интент (коммерческий / информационный / навигационный / нишевый) | кластер | страница-кандидат | кто в топе | наша страница есть/нет.
- Один кластер = одна страница.
- Кластер без заметного спроса → вопрос в FAQ, не страница.
- Информационные → статьи-сравнения с таблицами и кнопкой расчёта или заявки.
- Нишевые (например, эффекты обработки, детский, оверсайз) → отдельная страница только при спросе и реальном предложении, иначе раздел.
- Готово, когда: каждый запрос таблицы имеет кластер и интент, у каждого кластера одна страница-кандидат или пометка «FAQ».

## 3. Выход — `DEMAND-<домен>-<дата>.md` (references/output-template.md)
1. **Карта страниц**: URL · H1 · главный запрос · запросы кластера · title ≤ 65 · description 140–160 (с ценой «от», «от N шт», городом) · что на первом экране.
2. **План статей** (3–6) с запросом и таблицей, которую каждая закрывает.
3. **Содержание `llms.txt` / `llms-full.txt`**: факты, которые выводят нейросети и ждут люди (цена «от», минимальный тираж, сроки, адрес, что бесплатно), ссылки на посадочные.
4. **robots.txt**: какие боты открыты (поисковики, Алиса, GPTBot, ClaudeBot, PerplexityBot…), что закрыто (служебные, заявки, конфиги).
5. **FAQ**: вопросы словами людей из подсказок и PAA; формулировки офферов для первого экрана.
6. **Чего не знаем и как проверим**: избранные запросы в Вебмастере, повторный опрос нейросетей через 4–8 недель, контрольная точка через 4 недели — сверить показы и позиции с картой.
- Готово, когда: файл содержит все 6 разделов, у каждой страницы карты title ≤ 65 и description 140–160, частотности не выдуманы.

## 4. Передача
Карта страниц — вход для сборки сайта: title и description берутся отсюда, заново не придумываются. FAQ-вопросы, факты для llms.txt и список закрытых путей тоже переносятся как есть. Живые сайты на этом шаге не меняются.
- Готово, когда: пользователю отдан путь к `DEMAND-…md` и названо следующее действие (структура сайта по карте).

## Грабли
- Вордстат показывает показы Яндекса, не Google. Для коммерческих ниш частоты малы (десятки–сотни) — это нормально для B2B-производства, не повод расширять кластер без данных.
- Дробить сайт на десятки тонких страниц нельзя: Яндекс отмечает их как малоценные. Тиражные страницы («от N штук») — только если эти фразы есть в подсказках и Вордстате.
- Выводы по малой выборке (сотни визитов) — гипотезы до контрольной точки.
