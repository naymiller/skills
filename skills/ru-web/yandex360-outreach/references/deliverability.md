# Доставляемость и почта

## DNS домена отправки (панель регистратора или хостинга домена → DNS)
| Тип | Имя | Значение |
|---|---|---|
| MX | @ | `mx.yandex.net.` приоритет 10 |
| TXT (SPF) | @ | `v=spf1 redirect=_spf.yandex.net` — ОДНА запись на домен; если у хостинга уже есть SPF, объединить |
| TXT (DKIM) | `mail._domainkey` | ключ из Яндекс 360 → Администрирование → Домены → DKIM |
| TXT (DMARC) | `_dmarc` | `v=DMARC1; p=none; rua=mailto:<ящик на этом домене>` |
Проверка: письмо себе на Gmail → «Показать оригинал» → SPF/DKIM/DMARC: PASS. Проверить записи можно `dig TXT _dmarc.<домен>` в Терминале на Маке.

## Яндекс 360 и ящики
- IMAP: Почта → Настройки → Почтовые программы → «С сервера imap.yandex.ru по протоколу IMAP» + «Пароли приложений и OAuth-токены».
- Пароль приложения: id.yandex.ru → Безопасность → Пароли приложений → тип «Почта», войдя в ТОТ ЖЕ ящик. Иначе `535 Invalid user or password`.
- Новый ящик: админка 360 → Сотрудники → Добавить (делает владелец), логин в `config.json` → `mailboxes`, затем `setup.command`. Скрипт и Claude ящики не создают.
- Письма, отправленные по SMTP скриптом, не попадают в «Отправленные» — журнал отправок только `outreach_log.csv`.
- Баланс организации 360 со временем кончается — проверь автопополнение до старта волны.

## Коды недоставки (что делать)
| Код / текст | Значит | Действие |
|---|---|---|
| `550 5.1.1 user unknown` | адреса нет | нормально для 1–3 из 30; адрес в bounced |
| `5.2.2 mailbox full`, `4.x.x` | временно | повторится само |
| `554 5.7.1 … spam / blocked / policy`, «rejected by SpamAssassin» | блок получателя | при нескольких — остановить отправку и разбираться (DMARC, тексты, объём) |
Попроси владельца переслать текст письма о недоставке — без него причину не определить.

## Почему cron не работает и что вместо
- cron запускается вне пользовательской сессии и не видит login keychain → «Пароль не найден в Связке ключей» на каждом запуске.
- launchd (LaunchAgents в сессии пользователя) видит Связку; ставится `auto_on.command`. Пропущенный во сне запуск launchd выполняет при пробуждении, cron — нет.
- Мак спит → ничего не уходит: зарядка + отключённый сон, или `sudo pmset repeat wakeorpoweron MTWRF 11:00:00`.
- Убрать старые строки cron: `crontab -l | grep -v send_outreach | crontab -`.

## Прогрев
| Неделя | В день | Что |
|---|---|---|
| 1 | 5–10 | переписка со своими адресами, ответы на них |
| 2 | 10–15 | старт волны: партнёры первыми |
| 3+ | 20–30 | остальные + письма 2–4 по графику |
Рабочее время 10–17 МСК (вт–чт лучше), пауза 1,5–4 мин между письмами. Скрипт держит потолок сам (`warmup`).

## Законы (кратко, без юридических гарантий)
- Реклама по электронной почте в РФ требует предварительного согласия получателя (ст. 18 закона «О рекламе»). Поэтому: только деловые предложения конкретной компании, не массовая рассылка.
- Персональные данные — 152-ФЗ: личные адреса физлиц не собирать и не хранить; общие корпоративные адреса компаний — можно.
- Отказ — навсегда и исполняется сразу. Ответственность за соблюдение законов несёт отправитель.
