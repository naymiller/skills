# Подключение: два разных пути

Не менять модель оплаты пользователя молча. Управляющая модель — Cowork/Codex по подписке,
без Anthropic/OpenAI API billing. Генерации Higgsfield оплачиваются отдельно в выбранном контуре.

## A. Аккаунт Higgsfield через MCP / CLI
По [официальной странице](https://higgsfield.ai/skills) MCP поддерживает Claude Cowork;
вход идёт через аккаунт Higgsfield, API-ключ для этого MCP не нужен. Страница заявляет расход
кредитов платформы. Проверить текущую доступность, аккаунт и тариф перед запуском.
Не угадывать MCP URL — взять из официального подключения/каталога и сверить домен.

GitHub skills из higgsfield-ai/skills преимущественно вызывают CLI higgsfield с OAuth.
Поддержка MCP в Cowork сама по себе НЕ доказывает, что CLI-скилл без изменений выполнится в VM Cowork.
Проверить выполнение локальных команд, доступность CLI и сохранение OAuth в реальном окружении.
CLI login/status выполнять по текущей документации; браузерную авторизацию проходит пользователь.
Не просить пароль, cookie или access token в чат. Не считать авторизацию терминала доступной удалённому MCP.

## B. Developer API с сохранённым ключом
Этот путь нужен, если пользователь хочет работать с отдельным денежным балансом API и ключом, сохранённым один раз в защищённом хранилище.
Сначала проверить, есть ли уже рабочая интеграция, и сохранить её, если она соответствует задаче.
Документация Higgsfield описывает API как отдельный продукт с собственным каталогом и денежным балансом.
Плановые кредиты/Unlimited сайта не считать API-балансом. API-ключ не заменяет OAuth для CLI.

Официальные основы:
- [Python SDK](https://github.com/higgsfield-ai/higgsfield-client).
- [TypeScript SDK](https://github.com/higgsfield-ai/higgsfield-js).
- [API и отличие от платформы](https://higgsfield.ai/blog/generate-ai-videos-higgsfield-api).
- [Аутентификация API](https://docs.higgsfield.ai/docs/authentication).

Не переписывать клиент с нуля. Нужен поддерживаемый инструмент/адаптер, который читает секрет
из защищённого источника и отдаёт агенту только статус, job/request ID и результаты.
Секрет не хранить в skill, промпте, общей папке проекта, Git, CSV или JSON выдачи.
Формат ключа и переменные определяет выбранная версия SDK; не пробовать наугад «с Key/без Key».
Не загружать .env в чат или в документы Cowork. Приватный секретный store и окружение процесса
нужно настроить в той среде, где реально выполняется интеграция.

## Решение до установки
Показать пользователю: выбранный путь, какой аккаунт/баланс используется, доступные модели,
что будет сохранено и что произойдёт после новой сессии. Смена пути требует согласования.
Если API-каталог не содержит функцию product-photoshoot/Marketing Studio/Soul training из CLI,
не выдумывать endpoint и не утверждать полную совместимость. Согласовать доступную альтернативу.
Официальные CLI-skills нельзя автоматически назвать skills для Developer API.

При истёкшем OAuth доступе потребуется повторный вход; постоянная настройка не означает вечную сессию.
При 401 API остановиться, проверить выбранную организацию, формат и актуальность ключа безопасно,
затем предложить обновление через защищённый интерфейс, не повторный ключ в чат.
