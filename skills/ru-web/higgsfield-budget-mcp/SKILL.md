# Higgsfield с лимитом расходов

Локальный MCP-сервер `server/higgsfield_mcp.py` (только стандартная библиотека Python 3.9+) и порядок работы с ним. Модель не видит ключ и не может потратить больше, чем пользователь одобрил.

**Что нужно:** Python 3.9+, ключ Higgsfield Developer API (`id:secret`, https://console.higgsfield.ai), Claude Code или приложение Claude с поддержкой локальных MCP.

## Чем отличается от обычной обёртки API
- **Пакет с лимитом.** Каждая генерация идёт внутри пакета `hf_batch_open` с потолком в USD и по числу запросов; вне пакета `hf_submit` отказывает.
- **Цена до отправки.** Перед отправкой обязательна оценка (`/estimate`); неизвестная цена — отказ.
- **Без двойного списания.** Idempotency-Key (`intent_id`) создаётся и пишется в журнал до отправки; повтор после таймаута или 5xx — только с тем же ключом.
- **Ключ вне модели.** Сервер сам читает ключ из Связки ключей macOS (service `higgsfield-api`) или переменных окружения; инструменты возвращают только статусы, `request_id`, оценки и пути.
- **Песочница файлов.** Загрузка референсов и скачивание результатов — только внутри отдельной рабочей папки; `..` и символические ссылки наружу отклоняются.

## Установка
1. Ключ (в чат его не отправляйте):
   - macOS, Терминал: `security add-generic-password -a "$USER" -s higgsfield-api -w` → вставить ключ → Enter;
   - Windows / Linux: переменная окружения `HF_KEY=id:secret`.
2. Подключение:
   - Claude Code: `claude mcp add higgsfield -- python3 /полный/путь/server/higgsfield_mcp.py`;
   - приложение Claude: в настройках разработчика добавьте MCP-сервер с командой `python3` и аргументом — полный путь к `server/higgsfield_mcp.py`.
3. Перезапустите приложение и вызовите `hf_status`, затем `hf_workspace_init` — он создаст отдельную новую папку (по умолчанию `~/HiggsfieldWork`); подключайте к Claude только её.

Готово, когда: `hf_status` показывает `credential_configured: true`, `auth_check: ok` и путь рабочей папки.

Переменные для тестов и нестандартных установок: `HFMCP_WORKSPACE`, `HFMCP_STATE_DIR` (журнал заданий, по умолчанию `~/.higgsfield-mcp/jobs/`), `HFMCP_KEYCHAIN_SERVICE`, `HF_API_BASE`. Тесты: `python3 -m unittest discover -s tests` (поднимают локальный фейковый API, денег не тратят).

## Порядок генерации
1. **Статус.** `hf_status`. Ключа нет → дай пользователю инструкцию из раздела «Установка» и остановись. 401 → ключ отозван или неверен, пусть обновит тем же способом.
   Готово, когда: есть рабочая папка и рабочий ключ, либо инструкция отдана и работа остановлена.
2. **Референсы.** Файлы пользователь кладёт в `references/` рабочей папки. Клиентские файлы уходят в Higgsfield (`hf_upload`) только после его согласия. Для одежды и мерча сначала составь карту референсов (скилл apparel-references этого репозитория).
   Готово, когда: референсы на месте, согласие на загрузку получено или загрузка не нужна.
3. **Модель.** Выбирай по задаче из https://docs.higgsfield.ai/docs/models.md; путь модели и параметры — с её страницы, а не по памяти.
   Готово, когда: у модели есть документированный путь и каждый параметр найден на её странице.
4. **Оценка и пакет.** `hf_estimate` для пилота. Покажи пользователю модель, параметры, число генераций, оценку в USD и лимит пакета. После явного «да» — `hf_batch_open` с этими лимитами (`approval_note` — что одобрено).
   Готово, когда: пользователь сказал «да» на показанные цифры, пакет открыт с теми же лимитами.
5. **Пилот → серия.** 1 кадр → `hf_get` до терминального статуса (интервал 2→10 с) → `hf_download` в `projects/<проект>/outputs/…` → проверка → серия внутри того же пакета. Перед приёмкой серии — контакт-лист отдельным файлом.
   Готово, когда: пилот скачан и проверен, серия принята по контакт-листу.
6. **Неизвестный исход.** Повтори `hf_submit` с тем же `intent_id`; новый intent для этой отправки не создаёшь. Лимит исчерпан → новый пакет только с согласия пользователя.
   Готово, когда: у каждой отправки один `intent_id` и один итоговый `request_id`.
7. **После перезапуска.** `hf_jobs` и `hf_batch_status`; продолжай по `request_id` без новых отправок.
8. **Манифест.** `generation-manifest.json` проекта: модель, параметры, пути референсов, `intent_id`, `request_id`, статус, файлы, оценка. Ссылок и ключей в нём нет.
   Готово, когда: число записей = числу отправок = числу скачанных файлов, поиск по манифесту не находит `http` и ключей.

## Жёсткие ограничения
- Пополнение баланса, смена лимитов, публикация результатов — только с пользователем; без его «да» этого не происходит.
- Ключ, signed URL и клиентские данные не попадают в чат, логи, манифест и Git.
- Синтетические «отзывы» и UGC подаются как сгенерированные.
- Вызовы `hf_*` делает основная модель; субагентам эти инструменты не передаются.
