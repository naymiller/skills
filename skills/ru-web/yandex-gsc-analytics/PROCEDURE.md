# Аналитика сайта: выгрузка → анализ → план → выполнение → контрольная точка

Один проход = выгрузка из четырёх кабинетов → очистка → анализ → план → выполнение → контрольная точка через 2–4 недели. Всё делается через залогиненный браузер агента; от владельца нужен вход в Яндекс (и в Google) и согласие на публикацию. Пиши по-русски, коротко.

## 0. Перед стартом (одной строкой в чат)
- Сайты и счётчики: завести файл `sites.md` в рабочей папке проекта: домен, номер счётчика Метрики, адрес карточки Яндекс Бизнес, аккаунт Search Console. Сайта нет в списке — спроси домен и допиши список в конце.
- Распределение: сбор поисковых подсказок и выдачи — отдельные агенты на дешёвой модели (например Haiku), до 5 одновременно, на больших задачах до 10; проверка пакета и патча — отдельный агент-проверяющий с брифом (см. «Проверка» в `references/growth-actions.md`); вёрстка посадочных по брифу — отдельный агент с брифом. Себе — выгрузка из кабинетов (нужен залогиненный браузер), выводы, план, тексты title и description.
- Ограничения: на живой сайт ничего не публиковать и URL в поисковики не отправлять без отдельного согласия; реквизиты, цены и тексты сайта без подтверждения не меняются; токены и ключи в чат не писать (см. SKILL.md).
- Готово, когда: список сайтов и счётчиков определён, распределение названо владельцу.

## 1. Выгрузка (references/export-playbook.md)
1. Попроси владельца войти в Яндекс (и Google) в браузере — один раз. Проверь открытые вкладки, открой Метрику.
2. Выгрузи по каждому сайту всё из списка плейбука: отчёты Метрики (источники, поисковые фразы, страницы входа и выхода, устройства, гео, часы, глубина, UTM, параметры визитов, конфиг целей), полную историю визитов через Вебвизор-API (главный файл: по каждому визиту источник, страницы, цели), посетителей за год; Вебмастер (запросы за 12 месяцев с позициями, популярные запросы, запросы по URL, страницы в поиске, обход, внешние ссылки, диагностика); карточку Яндекс Бизнес (статистика и данные карточки); Google Search Console (сайт, которого нет в аккаунте, так и пиши).
3. Данные из браузера в рабочую среду передавай блоками `@@BLOCK сайт|отчёт|вариант@@ … @@END@@` (gzip+base64 для больших). Затем `scripts/extract_blocks.py` и `scripts/build_package.py` → папка `package/` и zip. Прямые запросы из рабочей среды к сайтам владельца часто не проходят (прокси или авторизация): выгрузка идёт через браузер.
4. Положи в пакет README: период, цели по id, маркеры внутренних визитов, чего нет. Отдай zip владельцу сразу — его можно передать в другую модель.
- Готово, когда: для каждого сайта в `package/` есть все файлы из списка плейбука либо в README строка «нет — причина», zip отдан владельцу.

## 2. Очистка и анализ (references/analysis-method.md)
- Убери свои и тестовые визиты (маркеры `_ym_debug`, `cachebust`, рефереры из интерфейсов Метрики и Вебмастера, uid с 5+ визитами, зарубежные сканеры). Пиши обе цифры: сырые и чистые.
- Обязательные таблицы: источники → визиты → с целью → доля; путь конверсионного визита; кластеры запросов Вебмастера (показы / клики / позиция); карточка Яндекс Бизнес (визиты, переходы на сайт, звонки, мессенджеры); ошибки формы из параметров визитов; индексация (в поиске / добавлено / малоценные).
- Ищи разрыв «показы есть — кликов нет» (CTR около 0 на позициях 4–10 → проблема сниппета и посадочной, а не позиций) и «трафик есть — заявок нет» (путь до контакта, цена не видна, форма ломается).
- Итог — `ANALYSIS_yandex.md` в пакете и короткий пересказ в чате. Образец структуры — в `references/analysis-method.md`, раздел 5.
- Готово, когда: все обязательные таблицы есть с сырыми и чистыми цифрами, оба разрыва проверены (найдены или «не обнаружены»), `ANALYSIS_yandex.md` лежит в пакете.

## 3. План «как получить больше клиентов» (references/growth-actions.md)
Рычаги по приоритету с ожидаемым эффектом и метрикой проверки, затем «что уже сделано», «что нужно от владельца», «как мерить через 2–4 недели». Образец — `references/example-plan.md` (условные цифры). Файл `ПЛАН-больше-клиентов-<дата>.md` отдай владельцу, суть — в чат, 10 строк.
- Готово, когда: у каждого рычага есть эффект и метрика, три завершающих раздела на месте, файл отдан.

## 4. Выполнение (references/growth-actions.md)
Сам, без отдельного вопроса, делаешь только внутренние обратимые настройки кабинетов, которые никто снаружи не видит: избранные запросы в Вебмастере, избранные цели в Метрике, указание sitemap. Всё, что уходит наружу или публикуется (переобход и IndexNow, новые ресурсы, карточка Яндекс Бизнес, файлы на сайте), — после согласия владельца с точным списком.
Для изменений на сайте собирай **патч** (только новые и изменённые файлы, пути как на сайте). Прогоняй проверку, рендер на десктопе и мобайле, отдавай архив и инструкцию. Заливку делает владелец либо ты — по его согласию и с его доступом к хостингу.
После заливки: проверка живого сайта с обходом кэша (`?cb=<случайное число>`, отпечаток текста, битые ссылки) — до неё не говори «залито» или «не залито»; затем переобход новых URL в Вебмастере и IndexNow — только с согласия владельца, как и любой URL в поисковики.
- Готово, когда: каждое обратимое действие выполнено и записано, патч прошёл проверку и рендер на двух ширинах, архив и инструкция отданы; статус заливки подтверждён проверкой живого сайта.

## 5. Контрольная точка (2–4 недели)
Через 2–4 недели повтори выгрузку тем же способом и сравни с прошлым пакетом: CTR и клики по избранным запросам, визиты из поиска, конверсии по избранным целям, переходы из карточки Бизнеса. Итог запиши в `sites-history/<домен>-<дата>.md` и предложи владельцу сохранить его.
- Готово, когда: сравнение с прошлым пакетом по всем четырём показателям записано.

## Грабли
- Цены, условия и реквизиты на сайте без подтверждения владельца не меняются; цены берутся только из его прайса.
- `browser_batch` с прокрутками, JS и скриншотом может быть заблокирован классификатором — делай по одному действию.
- JS-`click()` не всегда доходит до React: звёздочку избранной цели и кнопки «Сохранить» нажимай реальными координатами. Значения в поля React ставь через `form_input` или нативный сеттер `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set` и событие `input`.
- Кнопка «Сохранить изменения» в Яндекс Бизнес скрыта, пока поле не потеряло фокус — после ввода нажми Tab.
- Вебвизор хранит записи 15 дней; история визитов через API доступна за весь период счётчика.
- Окно браузера узкое (около 430 px) — координаты скриншота искажаются: увеличь окно до 1400×1000 и в конце верни прежний размер.
