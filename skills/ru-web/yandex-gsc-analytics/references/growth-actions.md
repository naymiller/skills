# План роста и выполнение

## Как писать план
Файл `ПЛАН-больше-клиентов-<дата>.md`: 1) что говорят данные (5 строк с цифрами); 2) рычаги по приоритету — каждый с ожидаемым эффектом и метрикой проверки; 3) что уже сделано (галочки); 4) что нужно от владельца (заливка, доступы, подтверждение цен); 5) как мерить через 2–4 недели. Образец — `references/example-plan.md`.

## Что делаешь сам, без вопросов (обратимо, в кабинетах)
| Действие | Где и как |
|---|---|
| Избранные запросы в Вебмастере (история позиций) | `efficiency/queries` → чекбоксы у топ-30 коммерческих и нишевых запросов → «Добавить запросы в избранное». Сразу после выкладки новых посадочных — добавить их запросы. |
| Избранные цели в Метрике | Настройки счётчика → Цели → звёздочка у целей «Отправил контактные данные» и «Переход в мессенджер» (сайтам с другими именами целей — их аналоги). Снять звёздочку с дублей формы. Клик по звёздочке — реальными координатами, не JS. |
| Sitemap и переобход новых сайтов | Вебмастер → `indexing/sitemap`: указать `https://<домен>/sitemap.xml`. Переобход страниц (лимит около 150 URL в день) и обход по счётчику Метрики — только с согласия владельца: это отправка URL в поисковик. |
| Favicon | Если Вебмастер пишет «нет favicon 120×120 / SVG» — сделать SVG, 120×120, ico, apple-touch (180), README с тегами `<link>`, архив `ЗАГРУЗИТЬ-<домен>-favicon.zip`. |
| Карточка Яндекс Бизнес | `/p/edit/`: «Сайт и социальные сети → Добавить → Telegram» (`https://t.me/<ник>`); часы работы текстом, например «будни 10:00-20:00» (после ввода Tab, иначе кнопка «Сохранить изменения» не появится). `/p/edit/price-lists/` → «+»: название с «от N шт», категория, цена за 1 «шт.» (единицу выбрать в списке), описание до 3000 знаков, короткое описание до 250 (его показывают Карты), ссылка на **существующую** страницу с UTM `utm_source=yandex_business&utm_medium=card&utm_campaign=services`. Цены — только из прайса владельца. Товар без цены не показывается. Изменения уходят на модерацию и становятся публичными — поэтому правки карточки вносятся только после согласия владельца с точным списком. |
| Google Search Console | С согласия владельца: новый сайт — добавить ресурс в аккаунт владельца, подтвердить (метатег или DNS TXT), отправить sitemap. Уже подключённые — не добавлять повторно. |
| IndexNow | После выкладки — отправка новых URL по ключу только с согласия владельца (см. SKILL.md, жёсткие ограничения). |

## Что делаешь как патч (владелец заливает или даёт доступ)
### Посадочные под кластеры запросов
Бриф исполнителю (отдельный агент на дешёвой модели с брифом, образец структуры — `references/example-plan.md`):
- Источник разметки — только живые страницы сайта (скачай их браузером в отдельную папку), не старые исходники. Шаблон — существующая страница того же типа: head, шапка, подвал, форма, cookie — байт в байт; меняются title, description, canonical, og:*, ld+json и содержимое `<main>`.
- Одна страница — один кластер: H1 с главным запросом; первый экран с офферами (минимальный тираж, срок, цена «от», способ заказа), кнопки «написать» и «калькулятор»; 2–4 секции H2; FAQ 3–5 вопросов с разметкой `FAQPage` (тексты слово в слово); ссылки на цены, продукцию, контакты и соседние посадочные; 500–900 слов, деловой тон.
- Title до 65 знаков с главным запросом и конкретикой (минимальный тираж, цена «от»); description 140–160 знаков с цифрами. Главной — новый title и description по тому же правилу.
- Цены — из прайса сайта; формулировка единая на всех страницах (шаблон: «от N ₽ при тираже M шт; минимальный заказ K шт»). Нет цены — «считаем по макету».
- Реквизиты на посадочных — из одного источника правды (ФИО, ИП или ИНН, как в реквизитах сайта); без выдуманных отзывов и клиентов; не трогать каталог, калькулятор, политики, CSS/JS и внешние скрипты.
- `sitemap.xml` — живые и новые URL (lastmod, priority 0.8), lastmod у изменённых; `llms.txt` — раздел «Посадочные страницы»; перелинковка с главной и соседних страниц.
- На сайтах с `ngx_pagespeed` имена ассетов переписываются — нормализуй обратно (`theme.css?v=`, `app.js?v=`), убери `pagespeed`-скрипты и атрибуты.
- Сдача: папка `public_html/` с теми же путями, `CHANGELOG.md` (новый или изменён, title и description каждой страницы), архив `ЗАГРУЗИТЬ-<домен>-seo-<дата>.zip`.
- Проверка: отдельный агент-проверяющий (один H1, canonical совпадает с путём, нет личных данных и выдуманных отзывов, ссылки ведут на существующие файлы, title и description в лимитах) + рендер Playwright на 1440 и 375 px по локальной копии (`python -m http.server`), снимки посмотреть.
- Инструкция владельцу: залить `public_html` с заменой; после заливки — переобход и избранные запросы.

### Другие типовые патчи
- Информационный кластер: одна страница-сравнение (таблица метод / тираж / цена «от» / стойкость / сроки / для чего, блок «как выбрать за 30 секунд», призыв к действию); дубли статей — объединить, старые URL → 301 или canonical.
- Нишевый спрос без страницы: страница на действующем сайте с ценой и минимальным тиражом; после запуска отдельного сайта — перелинковка.
- Форма: разобрать `reason.*` из параметров визитов, проверить на мобильных, включить безопасный режим отправки на время проверки (тестовый режим, без отправки в CRM или в мессенджер).
- Каталог-дубли: объединить варианты одной модели или canonical на базовую карточку; уникальные title.

## Нельзя
Публиковать на живой сайт, отправлять URL в поисковики, менять цены, условия и реквизиты, запускать рекламу — без отдельного согласия владельца с точным объектом. Писать токены и ключи в файлы скилла и в чат.

## Контрольная точка (2–4 недели)
Повторить выгрузку → сравнить: CTR и клики по избранным запросам (ориентир — CTR выше 2% по коммерческим запросам), визиты из Яндекса, конверсии по избранным целям, переходы из карточки в мессенджер, индексация новых URL. Итог — в `sites-history/<домен>-<дата>.md`.
